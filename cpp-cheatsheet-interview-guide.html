1. Program skeleton and compilation

#include <iostream>
#include <string>
#include <vector>

int main() {
    std::cout << "Hello, C++!\n";
    return 0; // optional in main
}
g++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o app
./app
  • #include makes declarations from a header available. Include the smallest header that provides what you use.
  • std:: names the standard-library namespace. Avoid using namespace std; in headers; explicit qualification is generally clearer.
  • Prefer \n for ordinary line endings. std::endl also flushes the stream.

2. Types, initialization, pointers, and references

int count = 3;
double price = 19.99;
char grade = 'A';
bool ready = true;
std::string name = "Ada";

const int maxRetries = 3;       // cannot change through this name
constexpr int bufferSize = 64;  // compile-time constant
auto total = price * count;     // deduced as double

int safe{42};                   // brace initialization rejects narrowing
Sizes are implementation-dependent. Do not assume that int is always four bytes. When an exact width matters, use <cstdint>, for example std::int32_t, and inspect limits with std::numeric_limits<T>.

Pointers, references, and const

int value = 10;
int& ref = value;                  // alias: cannot reseat
int* ptr = &value;                  // address: may be null/reseated
const int* readOnly = &value;       // cannot modify through this pointer

if (ptr != nullptr) *ptr = 20;
  • Use a reference when an argument is required and should behave as an alias.
  • Use a pointer when absence (nullptr), reseating, or pointer arithmetic is meaningful.
  • Use const T& for non-owning read-only parameters that would be expensive to copy. Pass small scalar values by value.

Important corrections: = assigns while == compares; integer division truncates (5 / 2 == 2). C++ logical operators are &&, ||, and !, not Python's and, or, or not.

Prefer range-based for for each element. break exits the nearest loop/switch; continue skips to the next iteration. Recursion needs a base case and must make progress toward it.

#include <algorithm>
#include <numeric>

std::sort(values.begin(), values.end());
auto it = std::find(values.begin(), values.end(), 42);
bool found = it != values.end();
values.erase(std::remove(values.begin(), values.end(), 0), values.end());

Algorithms use half-open ranges: [begin, end). The first position is included, the end position is excluded. Lambda captures: [] none, [x] by value, [&x] by reference, [=] used locals by value, [&] used locals by reference.

5. Classes, OOP, and templates

class Account {
public:
    explicit Account(std::string owner, double balance = 0.0)
        : owner_{std::move(owner)}, balance_{balance} {}

    void deposit(double amount) { balance_ += amount; }
    double balance() const { return balance_; }

private:
    std::string owner_;
    double balance_{};
};
  • class members are private by default; struct members are public by default.
  • Encapsulation is private state with public operations that preserve its invariants.
  • Use a member initializer list. Members initialize in declaration order.
  • Mark a one-argument constructor explicit unless implicit conversion is intentional.
  • Prefer composition for a has-a relationship; use inheritance for a genuine is-a relationship.
class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

class Circle final : public Shape {
public:
    explicit Circle(double r) : radius_{r} {}
    double area() const override { return 3.141592653589793 * radius_ * radius_; }
private:
    double radius_;
};

template <typename T>
T maximum(T a, T b) { return a < b ? b : a; }
Use override on overridden virtual functions. A polymorphic base class needs a virtual destructor. Templates usually keep their definitions in headers because the compiler instantiates them where they are used.

6. RAII, ownership, copying, and moving

RAII means acquire a resource in an object's constructor and release it in its destructor. It is C++'s core resource-safety pattern.

#include <fstream>
#include <memory>

auto file = std::ifstream{"input.txt"}; // closes at scope exit
auto oneOwner = std::make_unique<Widget>();
auto shared = std::make_shared<Widget>();
  • Prefer local objects, standard containers, and std::unique_ptr over raw new/delete.
  • unique_ptr represents exclusive ownership; it moves but does not copy.
  • shared_ptr represents shared ownership. Use it sparingly; use weak_ptr to break ownership cycles.
  • Copying duplicates a value/resource. Moving transfers resources; a moved-from object remains valid but its value is unspecified.
  • Follow the rule of zero: let members manage resources so you write no destructor or copy/move operations. Manual resource owners need the rule of five.

7. Exceptions, errors, and source layout

try {
    values.at(100);
} catch (const std::out_of_range& error) {
    std::cerr << error.what() << '\n';
}

Use exceptions for exceptional failure, not routine branching. Catch by const& to avoid slicing/copying. Destructors should not throw. Expected failures may be clearer as an error code, std::optional<T>, or a result type.

// widget.hpp
#pragma once
class Widget { /* declaration */ };

// widget.cpp
#include "widget.hpp"
// non-template definitions

Headers declare interfaces; source files define ordinary implementation. Use include guards or #pragma once, and never put using namespace ... in a header.

8. High-value interview answers

vector vs list

vector is contiguous, cache-friendly, and offers O(1) indexing; it is the usual default. Middle insertion/erasure is O(n). A list supports O(1) insertion/erasure only when its iterator is already known, but has poor locality and no random access.

map vs unordered_map

map orders keys and gives O(log n) operations. unordered_map has average O(1) lookup but no order and can degrade in worst cases. It is not automatically faster for every use.

Stack vs heap

Local automatic objects normally live until scope exit. Dynamic objects may outlive their creating scope, but need explicit ownership. Prefer local RAII objects; do not equate implementation storage details with semantic lifetime.

const correctness

const prevents modification through a name. A const member function cannot modify ordinary member state and can be called on a const object. It creates safer, clearer APIs.

Smart pointers

Raw new/delete is fragile with exceptions and early returns. Smart pointers express ownership and release automatically. Prefer make_unique or make_shared.

struct vs class

The language difference is default access and inheritance: public for struct, private for class. Convention uses structs for simple passive data and classes for encapsulated behavior.

9. Interview checklist and common pitfalls

  1. Restate the input, output, constraints, and edge cases.
  2. Give a simple baseline, then its time and space complexity.
  3. Select a data structure for a clear reason: lookup, ordering, uniqueness, or contiguous access.
  4. State the invariant you maintain as you code.
  5. Mentally test empty inputs, one element, duplicates, negative values, overflow, and boundary indices.
  6. Check lifetime, ownership, iterator invalidation, headers, and signed/unsigned comparisons.
Watch for: returning a reference/pointer to a local; dereferencing null or invalid iterators; no virtual destructor in a polymorphic base; object slicing; copying a large container accidentally; assuming moved-from content; retaining vector iterators through reallocation; and accidentally inserting via map[key].
